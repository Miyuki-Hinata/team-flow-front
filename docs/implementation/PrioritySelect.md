# PrioritySelect

## 何を作ったか
優先度（HIGH / MEDIUM / LOW）専用のセレクト（`src/components/ui/PrioritySelect.tsx`）。汎用 `Select` をラップし、優先度の選択肢を内部で固定する薄いコンポーネント。呼び出し側は options を渡さずに使える。

## なぜこの設計にしたか
- **汎用 Select のラッパーにした**：見た目（theme トークン）と `<option>` 描画・属性転送は Select が既に担っている。PrioritySelect はそこへ「優先度という意味づけ（固定 options）」だけを足す薄い層にすることで、スタイルの重複を持たず、Select を直せば見た目が自動で追従する。
- **値の型を `types/task.ts` の `Priority` から import**：優先度の値の正典はドメイン型。ここで独自に文字列リテラルを再定義すると型がズレる恐れがあるため、単一の出所を参照する。
- **options を「型を元にした map」で生成**：`(['HIGH','MEDIUM','LOW'] as Priority[]).map(...)` とすることで、`Priority` に値が増えた／消えたときに追従しやすく、ラベル表（`Record<Priority, string>`）側で埋め忘れれば型エラーになる。
- **並び順は 高→中→低（重い順）**：優先度の高さが上から直感的に伝わるようにした。
- **ラベルは簡潔な `高 / 中 / 低`**：フォーム内では「優先度」フィールドラベルの隣に並ぶ前提なので、`優先度 高` のような冗長表記は避けた（PriorityBadge の「優先度 高」はバッジ単体で意味が伝わる必要があるための表記で、文脈が違う）。
- **placeholder を独自 props で追加**：`<select>` 要素自体は placeholder 属性を持たないため、未選択見出しを出したいケース用に任意 props として足し、Select にそのまま流す。
- **単一責任**：優先度の「意味づけ」だけを担い、見た目・DOM 属性の面倒は見ない。

## どのお手本に倣ったか
- **Select.tsx（直前の実装）**：これをラップする形。props を分割代入で受け `{...rest}` を下位（Select）へ転送する構成をそのまま踏襲。
- **PriorityBadge.tsx**：値→ラベルの対応表（`Record`）を内包し、値の意味づけをコンポーネント内に閉じ込めるパターン。PrioritySelect は「選択肢版」の同じ発想。

## 使用した theme トークン
直接は使わない（見た目はすべて汎用 `Select` に委譲）。→ Select と完全に同一の見た目になる。
