# Checkbox

## 何を作ったか
複数選択の土台となる汎用チェックボックス。ネイティブ `<input type="checkbox">` を `accent-color` でブランド色に着色しただけの、見た目専用コンポーネント。

## なぜこの設計にしたか
- **標準属性を丸ごと継承（`InputHTMLAttributes`）**：`checked`/`onChange`/`disabled`/`aria-*` などを列挙せず継承。ただし `type` は `Omit` で除外し `'checkbox'` に固定（呼び出し側が別 type に上書きできないようにする）。
- **ネイティブ要素を活かす（独自描画しない）**：box＋SVGチェックを自作せず `accent-color` で色だけ変える。キーボード操作・フォーカス・スクリーンリーダー対応をブラウザ標準に委ねられ、コードも最小。Input/Select が素の要素を style するのと同じ思想。
- **label を持たない（単一責任）**：隣に何を並べるか（患者カード等）は呼び出し側の責任。ラベル付けは呼び出し側が `aria-label` を rest 経由で渡すか `<label>` で囲む。
- **サイズは 18px 固定**：spacing トークンは「隙間」用で寸法には使わない。既存方針（レイアウト定数としての px 直書き許容）に沿い、押しやすさのため文字非連動の実寸で固定。
- **ネイティブ vs 独自描画のトレードオフ**：`accent-color` で「アクセシビリティ・キーボード操作を無料で得つつ着色だけカスタム」を選んだ。独自描画は見た目の自由度が上がるが a11y を自前で担保するコストが増える。

## どのお手本に倣ったか
`Input.tsx` / `Select.tsx`：①標準HTML属性を型で継承 ②「見た目だけを担う styled 要素」 ③分割代入した rest を転送 ④単一責任（入力欄の見た目のみ、label は持たない）。フォーカス時にティールで「今ここ」を示す挙動も Input に合わせた（Input は border、checkbox は outline で表現）。

## 使用した theme トークン
- `colors.brand.teal` — チェック時の塗り（`accent-color`）＋フォーカス輪郭（`outline`）
- 寸法 18px は意図的にトークン外（レイアウト定数）
