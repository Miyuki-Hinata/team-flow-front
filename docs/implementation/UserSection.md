# UserSection（管理ページのユーザー一覧セクション）

## 何を作ったか
管理ページのユーザー（職員）タブの中身。一覧を「職種 → 部署」の2階層でグルーピングして表示し、追加ボタンで `UserFormModal` を開き、行ごとに編集・削除（確認ダイアログ付き）を行う。API 呼び出し（`createUser` / `updateUser` / `deleteUser`）の取りまとめもここが担う。

## なぜこの設計にしたか

- **フォームを `UserFormModal` に切り出した**：このコンポーネントの責任を「一覧の取得・表示」と「保存処理の取りまとめ」に絞るため。10項目の入力値・検証・初期化をここに同居させると、一覧の関心事と混ざって読めなくなる。
- **グルーピングは「職種 → 部署」の順**：職種は入職後ほとんど変わらないのに対し、部署は異動で変わる。管理者が人を探すときの手がかりとして**安定している方を外側**に置いた。（先に部署で分ける案もあったが、「あの人の部署が今どこか分からないから探しに来た」という状況で機能しないため見送り。）
- **職種の並びは `roleOrder`（業務上の並び）**：五十音順だと「医師」が中ほどに来て不自然。かつタスク作成時の担当者選択が既に `roleOrder` 順なので、**アプリ内で人の探し方が揃う**。
- **部署内は「かな」順**：漢字の氏名で `localeCompare` すると読み方と一致しない並びになり（例：「東」を「ひがし」で探しても見つからない）、探しにくい。
- **「部署なし」は必ず末尾**：空文字をキーにして `sort` で明示的に後ろへ回す。例外的な状態なので先頭に来ると目に付きすぎる。
- **行から職種・部署を削った**：見出しに引き上げたことで、1行の中身が「氏名／管理者バッジ／ボタン2つ」に統一された。以前は職種名（2〜10文字）と部署名（2〜6文字）の長さがバラバラで、狭い画面だと行ごとに折り返し位置が変わり表示がガタついていた。あわせて `ItemRow` から `flex-wrap: wrap` も外した（折り返す要素がもう無く、残すと将来また崩れる余地になるため）。
- **`useMemo` でグルーピング**：並べ替えは `userList` が変わったときだけ必要で、モーダルの開閉や削除確認の state 変化では再計算する意味がない。依存配列は `[userList]`。
- **保存ハンドラは1つにまとめて分岐**：`editingUser` の有無で `updateUser` / `createUser` を呼び分ける。**成功したときだけモーダルを閉じる**ようにして、失敗時は入力内容を残して直せるようにした。
- **自分自身は削除できない**：ログイン中のアカウントを消すと操作不能になるため、`currentUser?.id === user.id` の行だけ削除ボタンを `disabled` にする。サーバー側の制約ではなく UI 上のガードなので、`title` 属性で理由も添える。
- **管理者バッジは管理者にだけ出す**：一般ユーザー側に「一般」バッジを出すと、25行すべてにバッジが並んで視覚的ノイズになる。例外だけを示す。
- **部署一覧は props で受け取る**：`ProjectSection` と同じ方針。親（`AdminPage`）が保持しているので、別タブで部署を追加してもフォームの選択肢が最新になる。

## どのお手本に倣ったか
- **PatientCard.tsx**：theme トークンから色・余白を引き、ハードコードしない。ナビゲーション等の判断を持ち込まない単一責任。
- **AISummaryCard.tsx**：`type UserSectionProps = {...}` の分割代入で props を受け取る流儀。
- **MasterSection.tsx / ProjectSection.tsx（同フォルダ）**：一覧・追加・削除確認の構造と、`useToast` によるエラー表示、操作後に `reload()` で取り直す流れを踏襲。

## 使用した theme トークン
- `spacing.xs` — 一覧の行間・ボタン間隔・職種見出しの下余白
- `spacing.sm` — 行の内側余白・要素間
- `spacing.md` — 職種グループ内（部署グループ同士）の間隔
- `spacing.lg` — セクション内のブロック間隔・職種グループ同士の間隔
- `colors.border.default` — 行の枠線・職種見出しの下線
- `colors.text.primary` — 氏名・職種見出し
- `colors.text.secondary` — 部署見出し
- `radius.md` — 行の角丸
- `fontSize.lg` / `.md` / `.sm` — セクション見出し / 職種見出し / 部署見出し
- `fontWeight.bold` — 各見出し

## 面接で説明できるポイント
- **余白の設計で階層を表す**：行間 `xs`(4px) ＜ 部署グループ間 `md`(16px) ＜ 職種グループ間 `lg`(24px) ＜ セクション間 `xl`(32px)。数値が段階的に開くことで、「行」「かたまり」「別のカード」が余白の大きさだけで読み分けられる。すべて既存トークンで、新しい値は足していない。
- **見出しは `h2 → h3 → h4` と実際の見出しレベルで入れ子にした**：見た目だけ小さくするのではなく文書構造として正しく組むことで、スクリーンリーダーが階層を読み上げられる。
- **表示の「ガタつき」の原因は文字数のばらつきだった**：CSS を足して直すのではなく、**行に載せる情報を減らして**解決した。職種・部署は行ごとに繰り返す必要のない情報で、見出しに引き上げれば重複も消える。
- **並び順にはすべて理由がある**：職種＝業務順（他画面と統一）、部署＝五十音順、氏名＝かな順、部署なし＝末尾。「なんとなく」の並びを1つも残していない。
- **この実装で見つけた既存バグ2件**（詳細は下記）：`Card` が `className` を転送しておらず `styled(Card)` が無効だった件と、`Button` に `:disabled` のスタイルが無かった件。どちらもエラーが出ないタイプの壊れ方で、実装中に「無効化したのに見た目が変わらない」ことから辿り着いた。

## 付随して直した既存の不具合

### 1. `Card` が `className` を転送していなかった
`styled(Card)` は生成したクラス名を `className` props として `Card` に渡すが、`Card` は `({ children })` しか受け取っておらず捨てていた。そのため管理ページ3セクションの `Wrapper = styled(Card)` に書いた `display: flex` / `gap` が**すべて無視され**、要素が余白ゼロで密着していた。型エラーも実行時エラーも出ない（`className` は optional）ため気づきにくい壊れ方。`className` を受け取って `CardContainer` へ渡すことで解決し、再発防止に `Card.test.tsx` を追加した（修正を戻すとテストが落ちることも確認済み）。

### 2. `Button` に `:disabled` のスタイルが無かった
「自分自身は削除できない」を `disabled` で実装したところ、DOM 上は `disabled=true` なのに `opacity: 1` / `cursor: pointer` のままで、押せないことが見た目から分からなかった。`Input` / `Select` / `Checkbox` には `:disabled` があるのに `Button` だけ抜けていた。variant ごとに背景色が違うため色は指定せず、`opacity: 0.5` + `cursor: not-allowed` で一律に弱める形で追加した。
