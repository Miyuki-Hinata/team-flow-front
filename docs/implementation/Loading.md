# Loading

## 何を作ったか
「読み込み中...」の共通表示（`src/components/ui/Loading.tsx`）。データ取得中のプレースホルダとして、各ページで再利用する薄いコンポーネント。

## なぜこの設計にしたか
- **`message` を任意 props にした**：既定は「読み込み中...」。多くのページで同じ文言を使うので、呼び出し側は `<Loading />` と書くだけで済む。特定シーンで「AIサマリを生成中...」等の別文言を出したい場合は上書きできる。
- **表示要素は最小限**：現状は文言のみ。スピナー等のアニメーションは要件が固まってから追加する（YAGNI）。将来スピナーを追加するときも、この Wrapper の中に SVG を1つ差し込むだけで済む構造にしてある。
- **単一責任**：「読み込み中の表示」だけを担い、取得ロジック・エラー分岐・空状態は持たない。ページ側で `isLoading ? <Loading /> : <Content />` のように使う想定。
- **audit L 対応**：現状「読み込み中...」が `AnnouncementDetailPage:98` / `TaskDetailPage:128` / `PatientDetailPage:153, 226` 等に散在。今回は新設のみ行い、置換は各詳細ページ着手時に順次適用する。

## 使用した theme トークン
- 余白：`spacing.xl`（padding。埋没しない存在感を持たせる）
- 色：`text.secondary`（補助文字色。目立ちすぎない）
- 文字：`fontSize.md`（本文サイズ。README §Design Tokens「小さすぎる文字を避け読みやすく」の方針）

## 面接で説明できるポイント
- **YAGNI**：スピナー・遅延表示・タイムアウトなど「あると便利」機能は要件が来てから足す。今は文言だけの薄いコンポーネントに徹する判断。
- **既定 props とオーバーライド**：頻出ケースは既定でゼロコスト、特殊ケースは props で上書き、という小さな API 設計。
- **theme に委ねる**：色や余白の直書きをせず、アプリ全体の統一感を保つ。ダークモードにも自動追従（theme 切替で色が変わる）。
