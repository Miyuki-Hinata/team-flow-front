# Handoff: TeamFlow 病棟業務支援システム

## Overview
TeamFlow は「古い電子カルテUI（小さいボタンが大量・文字だらけ・グレーでカクカク）へのアンチテーゼ」として設計された、病棟業務支援システムです。JIRA / GitHub のように直感的で、非エンジニアの医療従事者（看護師など）が長時間使っても迷わず安全に使えることを目的としています。情報を詰め込みすぎず、余白を広めに取り、緊急など重要な情報にメリハリをつけるのが核となる思想です。

このバンドルには、ログイン・ダッシュボード・患者・お知らせ・タスクの各画面（一覧・詳細・作成・編集）を含む単一ページアプリのプロトタイプが入っています。

## About the Design Files
このバンドル内の `TeamFlow.dc.html` / `TeamFlow_共有用.html` は、**HTML で作成したデザインリファレンス**です。意図した見た目と挙動を示すプロトタイプであり、そのままプロダクションコードとしてコピーするものではありません。

タスクは、これらの HTML デザインを**ターゲットのコードベースの既存環境（React / Vue / SwiftUI / ネイティブ等）に、その確立されたパターン・ライブラリを使って再現する**ことです。まだ環境が無い場合は、プロジェクトに最も適したフレームワークを選定して実装してください。

- `TeamFlow.dc.html` は独自の軽量コンポーネントランタイム（`<x-dc>` / テンプレート + ロジッククラス）で書かれています。これは**参照用**であり、この仕組みを移植する必要はありません。テンプレート内のインラインスタイル、`renderVals()` 内のデータ・状態遷移ロジックを読み取り、ターゲット環境のコンポーネントとして書き直してください。
- `TeamFlow_共有用.html` は上記を単一ファイルにバンドルしたもので、ブラウザで直接開いて挙動を確認するのに使えます（オフライン可）。

## Fidelity
**High-fidelity (hifi)**。最終的な色・タイポグラフィ・余白・角丸・インタラクションが確定しています。ターゲットのコードベースの既存ライブラリ・パターンを使って、UI をピクセルパーフェクトに再現してください。すべての値は後述の「Design Tokens」に定義されたものだけを使用し、独自の値を追加しないでください（これは元のデザインルールの厳守事項です）。

## Design Tokens
**重要：色・余白・角丸・フォントは必ずこの定義値のみを使用し、独自の値を勝手に追加しないこと。**

### 余白（spacing）
8の倍数を基準。値をバラバラにしない： `4px` / `8px` / `16px`（標準・最頻出）/ `24px` / `32px` / `48px`

### 角丸（radius）
| 対象 | 値 |
|---|---|
| ボタン・入力欄 | `8px` |
| カードなど大きい要素 | `12px` |
| タグ・バッジ | `4px` |

### タイポグラフィ
- フォントファミリー： `'Noto Sans JP', sans-serif`（Google Fonts、weight 400 / 500）
- **太さは2種のみ：通常 `400` / 強調 `500`（重い700は使わない）**
- 行間：本文は `1.6`（広め）

| 用途 | サイズ |
|---|---|
| ページタイトル | `28px` / weight 500 |
| 見出し | `22px` / weight 500 |
| 小見出し | `18px` / weight 500 |
| 本文（基準・小さい文字を避ける） | `16px` / weight 400 |
| ラベル | `14px` |
| 補足・キャプション | `12px` |

### レスポンシブ ブレークポイント
```
sm: 640px   // これ以上 = 大きめスマホ〜
md: 768px   // これ以上 = タブレット〜
lg: 1024px  // これ以上 = PC〜
xl: 1280px  // これ以上 = 大画面PC〜
```

### その他の効果
- カードホバー時の影： `box-shadow: 0 2px 8px rgba(0,7,45,.06)`
- ドロップダウン/メニューの影： `box-shadow: 0 8px 24px rgba(0,7,45,.16)`
- モーダルの影： `box-shadow: 0 16px 48px rgba(0,7,45,.28)`
- モーダル/ドロワーのオーバーレイ： `rgba(0,7,45,.5)`
- 本文コンテンツの最大幅： `1080px`（中央寄せ）。フォーム系画面は `760px`、タスク詳細/編集は `880px`。

## アプリ全体の構造（App Shell）
全画面（ログインを除く）は共通シェルを持つ：

- **サイドバー** `width:248px`・背景 `#00072D`・`position:sticky; top:0; height:100vh`。
  - 上部：ロゴ（`#0E9384` の 32px 角丸8px アイコン + "TeamFlow" 18px/500 白）
  - ナビ項目：ダッシュボード / 患者一覧 / お知らせ / 全タスク / マイタスク。各項目 `padding:10px 12px; border-radius:8px; font-size:16px`。
    - 通常： `color:#9298A6; background:transparent; font-weight:400`
    - 現在地（アクティブ）： `color:#FFFFFF; background:#0E9384; font-weight:500`
    - 「お知らせ」には未読バッジ（`#A32D2D` 背景・白文字・`border-radius:10px`）
  - 下部：施設情報テキスト（`#5A6072` 12px、上に `1px solid #1A2348` の区切り線）
- **ヘッダー** `height:64px`・背景 `#001F5B`・`position:sticky; top:0; z-index:5`・`padding:0 32px`。
  - 左：パンくず（`病棟管理 / <現在画面名>`、14px、区切り "/" は `#5A6072`、現在画面名は白）。lg未満ではその左にハンバーガーボタンを表示。
  - 右：日付（`#C5CAD4` 14px、md未満で非表示）＋ ユーザーメニュートグル（32px アバター `#0E9384` + 名前14px + キャレット）
- **メインエリア** `flex:1; overflow:auto; padding:32px`（md未満で `16px`）。内側に最大幅コンテナ。

### レスポンシブ挙動
- **lg 未満（<1024px）**：サイドバーが off-canvas ドロワー化。`position:fixed; transform:translateX(-100%)`、開くと `translateX(0)`（`transition:transform .25s ease`）。半透明オーバーレイ（`rgba(0,7,45,.5)`）を背後に表示。ヘッダー左にハンバーガーボタン出現。ナビ項目タップで自動的に閉じる。
- **md 未満（<768px）**：3列・2列のグリッド（ダッシュボードのサマリカード、フォームの複数列、カンバン）はすべて1列に。ヘッダー・メインの余白縮小。ヘッダーの日付非表示。患者カードの「次の対応」ブロックが折り返して左寄せに。
- **sm 未満（<640px）**：バイタル等の4列グリッドを1列に。ヘッダーのユーザー名ラベル非表示（アバターのみ）。
- **xl（≥1280px）**：本文は最大1080px幅を維持。

## Screens / Views

### 1. ログイン画面（Login）
- **Purpose**: ログインID / パスワードでログイン。成功後ダッシュボードへ。
- **Layout**: フルスクリーン（シェルなし）。背景 `#00072D`、中央に `max-width:420px` のカラム。
- **Components**:
  - 上部：ロゴ（40px アイコン `#0E9384` + "TeamFlow" 22px/500 白）中央寄せ
  - 白カード（`border-radius:12px; padding:32px`）：見出し「ログイン」22px/500、サブ「ログインIDとパスワードを入力してください」14px `#5A6072`、ログインID入力、パスワード入力（type=password）、ログインボタン（`height:48px; background:#0E9384` フル幅）
  - 下部：「さくら総合病院 業務支援システム」12px `#5A6072` 中央
- **Behavior**: ログインボタン → `loggedIn=true` にしてダッシュボードへ。ログアウト時にこの画面を再表示。

### 2. ダッシュボード（Dashboard）
- **Purpose**: 朝一番の状況把握。担当患者・本日のタスク・未読お知らせのサマリと、要対応の抜粋。
- **Layout**: ページタイトル「おはようございます、中島さん」28px + 日付サブ。→ サマリカード3列グリッド（gap 16px）→ 2列グリッド（未読お知らせ / 本日の要対応患者）。
- **Components**:
  - サマリカード×3（担当患者 / 本日のタスク / 未読お知らせ）：白カード `padding:24px`、ラベル14px `#5A6072`、大数字28px/500、状態バッジ（緊急=赤、未完=黄）。クリックで各画面へ。
  - 未読お知らせリスト（最大3件）：カテゴリバッジ + 部署 + タイトル16px/500 + 投稿者・日付。緊急は左上に赤ストリップ + 赤枠。
  - 本日の要対応患者リスト：患者アバター（性別色）+ 名前 + 状態バッジ + 病室・次対応。緊急は赤ストリップ+赤枠。クリックで患者詳細へ。

### 3. 患者一覧（Patients List）
- **Purpose**: 病棟の全患者を状態別に把握。緊急を最上段に。
- **Layout**: ページヘッダー（タイトル + 「全N名・緊急N名」+ 右に「患者を追加」ボタン）→ フィルタバー（白カード）→ 状態別セクション（緊急・要対応 / 経過観察 / 安定・その他）。
- **Components**:
  - フィルタバー：検索入力（患者名、虫眼鏡アイコン付き、沈んだ面 `#EEF0F4`）+ 状態セレクト + 部署セレクト + 担当医セレクト。すべて `height:44px`。
  - セクション見出し：色ドット（`#A32D2D`/`#854F0B`/`#3B6D11`）+ タイトル14px/500 + 件数12px。
  - 患者カード（行）：白カード `border-radius:12px`。**緊急のみ**上部に3px赤ストリップ + 赤枠(`#A32D2D`)。内容：患者アバター（48px 円）+ 名前18px/500 + 状態バッジ + メタ（年齢・性別・年齢層・病室・部署・担当医）+ 右側「次の対応」（対応名 + 時刻チップ `#EEF0F4`）+ 右端シェブロン。クリックで患者詳細へ。ホバーで枠線 `#C5CAD4` + 影。
- **患者アバターの規則（重要）**：**性別＝色**（男性 青 `#185FA5`/背景 `#E6F1FB`、女性 紫 `#9333A8`/背景 `#F3EAF6`）、**年齢層＝形（SVG の人型シルエットを変える）**。小児(<15歳)＝頭大きめの人型、成人(15–64)＝標準の人型、高齢(≥65)＝杖をついた人型。装飾アイコンは使わず、情報を伝えるアイコンのみ。

### 4. 患者詳細（Patient Detail / カルテ）
- **Purpose**: 個々の患者の基本情報・バイタル・AIサマリ・関連タスクを1画面で。
- **Layout**: 「患者一覧へ戻る」リンク → ヘッダーカード → バイタル4列グリッド → AIタスクサマリカード → タスクのカンバン（3列）。最大幅880px。
- **Components**:
  - ヘッダーカード：64px アバター + 名前28px + 状態バッジ + メタ。下に4項目グリッド（生年月日 / 血液型 / 入院日 / 担当医）。緊急なら赤ストリップ+赤枠。
  - バイタルカード×4（体温・血圧・脈拍・SpO₂）：ラベル12px + 値22px/500。**異常値は意味の色で着色**（例：発熱=赤 `#A32D2D`、やや高値=黄 `#854F0B`、正常=`#1A1D24`）。単位は12px `#9298A6`。
  - AIタスクサマリ：見出し（キラキラSVG + "AIタスクサマリ" 18px/500）+ 右に「再生成」ボタン（アウトライン）+ 本文16px/1.6。
  - カンバン：見出し + 右にタブ（すべて / マイタスク、セグメント切替 `#EEF0F4` 背景）。3列（未着手 / 進行中 / 完了）。各列は `#EEF0F4` 背景 `border-radius:12px`、列見出し（色ドット + タイトル + 件数）、タスクカード（優先度バッジ + タイトル16px + 期限・担当12px）。カードクリックでタスク詳細へ。

### 5. お知らせ一覧（Announcements）
- **Purpose**: 院内連絡の確認。緊急を目立たせ、未読/既読を切替。
- **Layout**: ページヘッダー（タイトル + 未読件数 + 「新規作成」ボタン）→ 未読/既読タブ（セグメント）→ お知らせカードリスト。
- **Components**:
  - タブ：未読 N / 既読 N（`#EEF0F4` セグメント、アクティブは白背景）。
  - お知らせカード：白カード。緊急は3px赤ストリップ+赤枠。未読は左に `#0E9384` の小ドット。カテゴリバッジ + 部署チップ + タイトル18px/500 + 本文16px `#5A6072` + 投稿者・日付14px。

### 6. お知らせ作成（Announcement Create）
- **Purpose**: お知らせの新規投稿。自分の投稿を同画面下で管理。
- **Layout**: 戻るリンク → タイトル → フォームカード → 「作成したお知らせ」リスト。最大幅760px。
- **Components**:
  - フォーム：タイトル入力 / カテゴリ・対象部署・優先度の3列セレクト / 掲載終了日（type=date、補足「この日を過ぎると一覧に表示されなくなります」）/ 本文（textarea rows=6）/ キャンセル・投稿するボタン。
  - 「作成したお知らせ」：自分の投稿カードリスト。各カードにカテゴリ/部署バッジ・タイトル・投稿日/掲載終了日 + 「編集」「削除」ボタン。緊急は赤ストリップ+赤枠。削除は実際にリストから除去。編集はお知らせ編集画面へ。
- **設計メモ**：件数が少ない前提で作成フォームと同画面にインライン配置。数十件規模・検索/ページング・下書き等が必要になれば専用の「お知らせ管理」ページへ分離推奨。

### 7. お知らせ編集（Announcement Edit）
- **Purpose**: 自分の投稿の修正。
- **Layout/Components**: 作成画面とほぼ同型。既存値がプリフィルされた状態（タイトル・カテゴリ・対象部署・掲載終了日・本文）。キャンセル・保存するボタン。

### 8. 全タスク / マイタスク（Tasks / My Tasks）
- **Purpose**: タスクの一覧管理。マイタスクは自分（中島 看護師）担当のみ。
- **Layout**: ページヘッダー（タイトル + 「N件・未完N件」+ 「タスク作成」ボタン）→ フィルタバー（状態セレクト + 優先度セレクト）→ タスク行リスト。
- **Components**:
  - タスク行：白カード。左に状態バッジ（min-width 64px、中央寄せ。未着手=灰 `#EEF0F4`/`#5A6072`、進行中=青 `#E6F1FB`/`#185FA5`、完了=緑 `#EAF3DE`/`#3B6D11`、保留=黄）+ タイトル18px/500 + 患者・カテゴリ14px + 優先度バッジ + 右に期限・担当。クリックでタスク詳細へ。

### 9. タスク作成（Task Create）
- **Purpose**: 新規タスクの登録。
- **Layout/Components**: 戻るリンク → 「タスクを作成」→ フォームカード（最大幅760px）。タスク名入力 / 詳細 textarea / 対象患者・カテゴリの2列セレクト / ステータス・優先度の2列セレクト / 担当者セレクト・期限（type=datetime-local）の2列 / キャンセル・作成するボタン。

### 10. タスク詳細（Task Detail）
- **Purpose**: タスク内容の確認、ステータス変更、編集・削除、変更履歴の閲覧。
- **Layout**: 戻るリンク → 詳細カード → 変更履歴。最大幅880px。
- **Components**:
  - 詳細カード：優先度バッジ + カテゴリチップ + タイトル28px/500、右に「編集」「削除」ボタン。→ ステータス変更行（`#EEF0F4` 背景 `border-radius:8px`、ラベル + ステータスセレクト + 補足「変更すると履歴に記録されます」）。→ 2列グリッド（対象患者 / 担当者 / 期限 / カテゴリ）→ 詳細本文。
  - 変更履歴：見出し18px/500 + カード。各エントリ：`#0E9384` ドット + 変更内容（例「ステータス：進行中 → 完了」）+ 日時・変更者12px。履歴なしは「変更履歴はありません」。
- **Behavior**: ステータスセレクト変更で、その場でステータス更新 + 変更履歴の先頭に新エントリ追加（`{ 日時, 変更者, フィールド, from, to }`）。削除でタスクをリストから除去し一覧へ戻る。

### 11. タスク編集（Task Edit）
- **Purpose**: タスクの全項目編集。
- **Layout/Components**: 戻るリンク → 「タスクを編集」→ フォームカード（タスク名 / 詳細 / ステータス・優先度・担当者の3列 / 対象患者・期限の2列 / キャンセル・保存する）→ 下部に変更履歴（詳細画面と同じ表示）。

### 12. パスワード変更モーダル（Password Change Modal）
- **Purpose**: ヘッダーのユーザーメニュー「パスワード変更」から起動。
- **Layout/Components**: 中央モーダル（`width:440px; border-radius:12px; padding:32px`、オーバーレイ `rgba(0,7,45,.5)`）。見出し「パスワード変更」22px + 閉じる×。現在のパスワード / 新しいパスワード / 新しいパスワード（確認）の3入力（type=password）。閉じる・変更するボタン。オーバーレイクリックでも閉じる。

### ユーザーメニュー（ヘッダー ドロップダウン）
ヘッダー右のユーザー名クリックで開閉。白い `width:200px` カード（`border-radius:12px`、影）。項目：「パスワード変更」（→ モーダル）、「ログアウト」（赤文字 `#A32D2D`、→ ログイン画面）。背後の透明バックドロップクリックで閉じる。キャレットは開時に180°回転。

## Interactions & Behavior
- **画面遷移**：SPA。サイドバーナビ、各種カードクリック、作成/戻るボタンで `screen` state を切替。`scrollIntoView` は使わず通常のスクロールで。
- **ホバー**：カードは枠線を `#E2E5EB` → `#C5CAD4` に変え、影を付与。ボタンは `#0E9384` → `#0B6B60`、アウトラインボタンは枠線を濃く。削除ボタンは赤枠+赤背景に。
- **フィルタ/検索**：患者一覧は名前部分一致（空白無視）+ 状態/部署/担当医の絞り込み。タスクは状態/優先度の絞り込み + マイタスクは担当者一致。すべてクライアント側で即時反映。
- **タブ**：お知らせ未読/既読、患者詳細カンバンのすべて/マイタスク、いずれもセグメント切替。
- **ステータス変更 → 履歴記録**：タスク詳細のステータスセレクト変更時、履歴に自動でエントリを先頭追加。
- **削除**：お知らせ（作成画面の自分の投稿）・タスク（詳細画面）は実際に配列から除去。
- **モーダル/ドロワー**：オーバーレイクリックで閉じる。ドロワーはナビ選択時に自動で閉じる。
- **フォーカス**：入力欄フォーカスで枠線 `#0E9384`・背景 `#EEF0F4` → `#FFFFFF`・`outline:none`。

## State Management
プロトタイプは単一コンポーネントの state で管理。ターゲット環境では画面/機能単位に分割してよい。主な state：
- `screen`：現在表示中の画面（"dashboard" | "patients" | "patient" | "announcements" | "announcementCreate" | "announcementEdit" | "tasks" | "mytasks" | "taskCreate" | "task" | "taskEdit" | "patientCreate"）
- `loggedIn`：ログイン状態（false でログイン画面）
- `selectedId`：表示中の患者ID / `selectedTaskId`：表示中のタスクID / `editAnnId`：編集中のお知らせID
- `query`, `statusFilter`, `deptFilter`, `doctorFilter`：患者フィルタ
- `taskStatusFilter`, `taskPriorityFilter`：タスクフィルタ
- `kanbanTab`（"all" | "my"）, `annTab`（"unread" | "read"）：タブ状態
- `menuOpen`（ユーザーメニュー）, `pwOpen`（パスワードモーダル）, `navOpen`（モバイルドロワー）
- `taskData`：タスク配列（ステータス変更・削除でミューテート、各要素に `history` 配列を持つ）
- `myCreated`：自分が作成したお知らせ配列（削除でミューテート）

### データ取得について
プロトタイプ内の `patients()` / `tasks()` / `announcements()` はモックデータ。実運用ではバックエンドAPI（元仕様では `fetchWithAuth` で `http://localhost:8080` 等）から取得し、これらを差し替える想定。認証はアクセストークン（メモリ）+ リフレッシュトークン（HttpOnly Cookie）、401時に1回リフレッシュ&リトライ。変更履歴の日時（プロトタイプでは「たった今」）は本番ではサーバー記録のタイムスタンプを整形して表示する。

## データモデル（参考）
- **Patient**: id, 苗字/名前/かな, 生年月日, 性別(male/female), 年齢, 住所, 電話番号, 緊急連絡先(人物名/電話番号), 部署(科), 担当医, 病室, 入院日, 血液型, status(緊急/経過観察/安定/情報), バイタル(体温/血圧/脈拍/SpO₂ + 各異常フラグ), AIサマリ, 次の対応(内容/時刻)
- **Task**: id, pid(患者ID), title, patient(患者名), status(未着手/進行中/完了/保留), priority(HIGH/MED/LOW), due(期限), assignee(担当者), category(観察/投薬/検査/処置/事務), desc(詳細), history[]({at, by, field, from, to})
- **Announcement**: id, title, body, category(緊急/連絡/シフト/その他), dept(対象部署), author, date(投稿日), endDate(掲載終了日), urgent(bool), unread(bool)

## Assets
- **フォント**：Noto Sans JP（Google Fonts、weight 400/500）。`https://fonts.googleapis.com/css2?family=Noto+Sans+JP:wght@400;500`
- **アイコン**：すべてインライン SVG（`stroke` ベース、`stroke-width` 1.6 前後）。外部アイコンライブラリ不使用。ターゲット環境では既存のアイコンセット（Lucide 等）で同等のものに置き換えて可。患者アバターの年齢層別シルエットだけは「形で年齢層を伝える」意図があるため、同等の描き分けを維持すること。
- **画像**：写真等の外部画像アセットは無し。

## やってはいけないこと（デザイン原則）
- 全カードを均質に並べない。緊急など重要情報にメリハリ（赤ストリップ+赤枠、最上段配置）をつける。
- 意味のない装飾（情報を持たない飾り）を足さない。
- 1つの色に2つの意味を持たせない（緑=完了/安定、赤=緊急）。
- 文字を詰め込まない。小さいボタンを大量に並べない（＝電子カルテUIへの逆戻り）。
- 定義外の色・余白・角丸・フォントサイズ/ウェイトを追加しない。
